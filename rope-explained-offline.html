01

问题起点：加法把语义和位置搅在一起了

你熟悉的那套做法是：词向量 x，位置向量 p，两个一加，x + p，送进 Transformer。这套做法有个说不出哪里别扭但确实别扭的地方。

想想 Attention 在算什么。它算 q_m · k_n，也就是位置 m 的 token 去看位置 n 的 token，两个向量点乘出一个分数。如果位置是加进去的，把它展开：

(x_m + p_m) · (x_n + p_n)
= x_m·x_n  +  x_m·p_n  +  p_m·x_n  +  p_m·p_n
   内容×内容     内容×位置     位置×内容     位置×位置

四项。第一项是你真正想要的语义匹配，第四项是纯位置关系，中间两项是"这个词的含义"和"那个位置"做点积。语义和位置搅在一起了。模型得自己想办法把这团东西解开，它能学会，但这是硬学出来的，不是结构本身保证的。

四项展开的实际大小

用两个固定的内容向量加上正弦位置编码（d=8）实算。两个交叉项并不小，和你真正想要的语义项在同一个量级。

第二个问题更要命：学不到可迁移的相对关系

语言里真正重要的是相对关系。"不"修饰它后面那个词，主语在动词前面，这些规律跟句子从第几个 token 开始毫无关系。但在绝对位置编码下，"位置 5 和位置 3 相邻"与"位置 105 和位置 103 相邻"是两组完全不同的位置向量，模型得把同一件事在每个绝对位置上重新学一遍。

同样是"隔 Δ 格"，位置向量之差却完全不同

两行都是正弦位置编码的差值 p_m − p_n，两行的 Δ 完全相同。如果差值能代表"隔 Δ 格"这个概念，两行应该一模一样。

第三个问题：外推

训练时最长见过 512，来了第 513 个 token 怎么办？可学习的位置向量根本不存在。

02

中间的尝试：给分数加一个相对位置偏置

2018 到 2019 年，大家的思路是"既然要相对位置，那就直接在 attention 分数上加个相对位置的偏置"。

Shaw 的相对位置表示、Transformer-XL、T5 的 relative position bucket，都是这个路子：

score = q_m · k_n + b(m − n)       b 是一张按距离查的表

这确实解决了相对性和外推，但代价是：多了一堆参数，而且 attention 不再是干净的 QK^T 了。多出来的那一项要单独算、单独加，跟各种高效 attention 实现（尤其是线性 attention）都不兼容。

方案 A · 绝对位置加法

语义位置纠缠 无法外推
形式干净，但性质不对。

方案 B · 相对位置偏置

有相对性 破坏 QK^T
性质对了，但形式脏了。

想要的 · 两头都要

有相对性 形式干净
这就是 RoPE 要回答的问题。

于是问题变成：能不能既保持 q·k 这个干净形式，又让结果天然只依赖相对位置？

03

发明过程：他没有去设计，而是列了一个方程去解

2021 年 3 月，苏剑林（追一科技）在博客上给出了答案，后来整理成 RoFormer 论文。做法很特别。

他写下自己想要的性质：我要找一个函数 f，它把绝对位置 m 塞进向量 q，把绝对位置 n 塞进向量 k，但两者做点积之后，结果里只剩 m − n。

这一行不是结论，是一句许愿

把鼠标移到任一符号上看它的含义。关键在左右两边的不对称。

左边是"我实际怎么做"：只能拿到绝对位置。右边是"我希望得到什么"：结果里只准留下差值。

未知量是 f 和 g 两个函数，已知的是"我要这个等式对所有 q、k、m、n 都成立"。这跟解 x² = 4 求 x 是一回事，只不过这里求的是函数。注意 q、k 在两边都自由出现，说明内容怎么参与不受约束；被约束的只有位置：位置只能以差值的形式活下来。

在二维的情况下，把向量看成复数（x + iy，长度是模，方向是相角），试一试这个形式：

f(q, m) = q · e^{i·m·θ}        把 q 这个复数逆时针转 mθ 弧度

代进去验证：

⟨f(q,m), f(k,n)⟩ = Re[ (q e^{imθ}) · conj(k e^{inθ}) ]
                 = Re[ q·k̄ · e^{i(m−n)θ} ]     ← m 和 n 各自的绝对值消掉了，只剩差

这就是全部的发明。答案是"旋转"，而旋转是被方程逼出来的，不是猜出来的。 苏剑林那篇博客的标题叫"博采众长的旋转式位置编码"——它用绝对位置的方式实现（直接作用在 q、k 上，不加额外偏置项），却得到相对位置的效果。

04

物理直觉：一块机械钟

现在忘掉公式。钟面上有指针，你要表达"现在是几点"，不需要改变指针的长度、颜色、材质，只要改变它指的方向。方向就是信息。

RoPE 干的事一模一样。它把 token 的 q 向量当成一堆指针，token 在句子里越靠后，指针就转得越多。位置信息完全编码在方向里，向量的长度一点没变。这带来一个非常干净的分工：

向量的长度和形状  →  这个词是什么意思（内容）
向量的朝向        →  这个词在第几个位置（位置）

两条信息走两个互不干扰的通道。对比一下加法：x + p 是把向量在空间里平移，长度和方向全都改了，内容和位置从此纠缠不清。RoPE 是转动，内容那一维（长度）完全没被碰过。

加法会改长度，旋转不会

同一个内容向量。左边做加法，尖端离开虚线圆、长度随位置乱跑；右边做旋转，尖端始终贴在圆上、长度恒定。淡点是其它位置的落点轨迹。

那为什么点积就能自动得到相对位置

还是看钟表。两个人各自转了一个转盘，一个转了 3 格，一个转了 1 格。你去测量这两个转盘之间的夹角，得到的是 2 格。如果两人都多转 4 格，变成 7 格和 5 格，夹角还是 2 格。

点积就是在测夹角（a·b = |a||b|cos∠）。所以只要位置是用旋转编码的，点积测出来的必然是位置差。这不是巧合，这就是"角度相减"这个初中知识。

两根指针一起转，夹角不动

拖动 m 和 n 看绝对角度怎么变，再点"同时 +10"：两根指针一起往前扫，夹角和 cos 值一位不差。

05

为什么要很多根指针

一根指针不够用。转盘转满一圈就回到原点，位置 0 和位置 6.28 会长得一样，产生歧义。

而且一根指针要么走得快（能分辨相邻词，但很快绕圈），要么走得慢（能覆盖长距离，但相邻两个词的角度差微乎其微，分不开）。真实的机械钟怎么解决的？用多根不同速度的指针。秒针快，负责精细；分针中等；时针慢，负责跨越大范围。三根一起读，既精确到秒，又能覆盖 12 小时不重复。

RoPE 完全照搬这个设计。head_dim = 64 就有 32 根指针（32 个二维平面），转速按几何级数递减：

θ_i = 10000^(−2i/64)           i = 0 … 31

i=0    θ = 1.0        λ ≈ 6.3 token 转一圈         ← 秒针
i=8    θ = 0.1        λ ≈ 63 token 转一圈
i=16   θ = 0.01       λ ≈ 628 token 转一圈
i=24   θ = 0.001      λ ≈ 6283 token 转一圈
i=31   θ ≈ 0.000133   λ ≈ 47117 token 转一圈       ← 时针

同一个位置下，8 根代表性指针各自转了多少

把 p 从 0 拖到几百，看秒针飞转、时针几乎不动。快指针分辨"隔 1 个还是隔 2 个词"，慢指针分辨"隔 1000 还是隔 5000 个词"。

32 根指针的波长阶梯

纵轴是对数刻度的波长（转一圈需要多少 token）。从 6.3 到 47117，跨了四个数量级，这就是 RoPE 能同时管住近距离和超长距离的原因。

顺便说，这也解释了两件事。长程衰减：距离拉大时，32 根指针的角度差各不相同，cos 值有正有负互相抵消，总分自然往下掉，模型天生倾向于关注近处。YaRN 外推：想让上下文从 256K 撑到 1M，就是去调慢那些"时针"，让它们的一圈覆盖更长的距离。

长程衰减不是加的，是自带的

把 32 根指针在距离 Δ 上的 cos 值全部相加得到的曲线。Δ=0 时满分 32，随后震荡下滑，没有任何人为设计的衰减项。

06

对输入向量到底做了什么

一句话：把向量切成一堆二维平面，每个平面按 位置 × 该平面的转速 转一个角度，转完拼回去。

作用在 q 和 k

不是输入 embedding。传统 PE 在最底层加一次，之后每层只能间接感受到位置；RoPE 在每一层的 attention 里都重新施加一次。而且 v 不参与旋转，位置只影响"谁该看谁"，不影响"看到的内容是什么"。

零参数

cos 和 sin 是按公式算的，没有任何可学习的位置向量。省参数，且天然支持任意长度。

保长

旋转是正交变换，向量模长严格不变，内容强度不会被位置污染。

它插在计算图的哪个位置

每一层都走一遍：q、k 各自旋转，v 原样通过。

07

公式

现在再看公式，应该只是把上面的话翻译一遍。

第 i 对的旋转角

φ_i = p · θ_i         位置 p 决定转几步，θ_i 决定每步多大

第 i 对的旋转

x'_2i   = x_2i   · cos φ_i − x_2i+1 · sin φ_i
x'_2i+1 = x_2i+1 · cos φ_i + x_2i   · sin φ_i

这就是标准的二维旋转矩阵，中学解析几何。写成整个 head 的矩阵就是块对角结构：对角线上一串 2×2 小块，块外全是零。零元素就是"每对独立、互不串扰"的数学表达。

块对角矩阵（head_dim = 8，p = 3 的真实数值）

灰色格子全是零，占了 75%，所以代码里从不真的构造它，而是逐元素向量化。

# 论文写法：相邻配对 (2i, 2i+1)
q_even, q_odd = q[..., 0::2], q[..., 1::2]
out_even = q_even * cos - q_odd  * sin
out_odd  = q_odd  * cos + q_even * sin

# HuggingFace / LLaMA / Qwen 写法：半分配对 (i, i + d/2)
def rotate_half(x):
    x1, x2 = x[..., :x.shape[-1]//2], x[..., x.shape[-1]//2:]
    return torch.cat((-x2, x1), dim=-1)

q_embed = q * cos + rotate_half(q) * sin

两种配对方式只差一个维度置换，数学上等价，但权重不能混用。Qwen 系列走的是 rotate_half 这条路线。

关键性质

R_m^T R_n = R_{n−m}           两个旋转相减，绝对位置消失
q_m · k_n = q^T R_{n−m} k     得分只依赖 m − n

逐步例子

拿一个 head_dim = 8 的向量，token 在位置 p = 3（第 4 个 token）。一步一步走完。

从输入向量到输出向量

第 0 对（最快的指针）转了 3 弧度、172 度，几乎转到反方向；第 3 对（最慢的指针）转了 0.003 弧度、0.17 度，肉眼看不出动。拼回去之后长度 1.786057 → 1.786057，内容一点没丢，只是盖上了位置 3 的时间戳。

09

相对性验证

同一对 q、k 向量，只改它们所在的位置，看得分怎么变。

绝对位置换了，得分不变；间距换了，得分才变

上方是四个维度对各自的贡献，下方是不同位置组合的得分表。留意 Δ 相同的行，六位小数完全一致。

两个转盘同时多转 4 格，夹角不变，所以得分不变。还有一个能坐实结论的边界例子：不加 RoPE 时 q·k = 0.010000，而 Δ=0 时 RoPE 的得分也正好是 0.010000，旋转角相减为零，旋转被完全抵消，退回原始点积。

10

总结，以及回到 Qwen3-VL

绝对位置加法把语义和位置搅在一起、学不到可迁移的相对关系、还没法外推。相对位置偏置解决了这些但破坏了 attention 的干净形式。苏剑林列了个方程问"有没有办法两头都要"，解出来是旋转：位置信息藏在向量的朝向里，点积测夹角时绝对角度自动抵消，只留下相对距离。为了在大跨度上不产生歧义，用一组几何递减转速的指针，像机械钟的秒针分针时针。

MRoPE 和 Interleaved-MRoPE 一个字都没改这套机制。它们改的只是 φ_i = p·θ_i 里的 p 从哪来。文本只有一根位置轴；视频有时间 t、高度 h、宽度 w 三根轴，于是三个数要分给 32 根指针。

同样 32 根指针，两种分配方式

切换看时间轴 t 能拿到的波长范围。Qwen2-VL 把指针连续切三段，t 只分到最快的那几根；Qwen3-VL 改成交错分配，让三根轴都拿到从秒针到时针的完整梯度。

面试如果被追问 RoPE，"它是解一个函数方程解出来的，答案必须是旋转"这句话比任何公式都有说服力。
